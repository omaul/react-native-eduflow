# CLAUDE.md — Инструкции проекта

## Что это за проект

Образовательная платформа-блокнот. Контент в Markdown, UI на React, деплой на GitHub Pages.
Цель: экспериментировать с педагогическими подходами, делая контент полезным и запоминающимся.
Первый раздел — структурированный материал по растениям.

Подробная суммаризация: [PROJECT_SUMMARY.md](PROJECT_SUMMARY.md)

## Специализированные гайды

Перед работой с UI/стилями — сверься с **[.claude/design-system.md](.claude/design-system.md)**
Перед работой с контентом/текстами — сверься с **[.claude/content-guide.md](.claude/content-guide.md)**

Эти гайды — рекомендации, не жёсткие правила. Если возникает противоречие или сомнение — спроси у пользователя.

## Архитектура

### Слои приложения

```
src/
  components/        — переиспользуемые UI-компоненты (кнопки, карточки, лейауты)
  components/md/     — кастомные компоненты для вставки в Markdown (квизы, callout-блоки и т.д.)
  pages/             — страницы (по одной на маршрут)
  hooks/             — React-хуки
  utils/             — чистые утилиты без React-зависимостей
  sketches/          — p5.js скетчи для генеративных фонов
  types/             — TypeScript-типы
  styles/            — CSS Modules + токены дизайн-системы
```

### Принципы

- **Простота прежде всего.** Не добавляй абстракции, пока они не нужны в двух+ местах.
- **Нет state-менеджера.** useState/useEffect достаточно. Если появится реальная потребность — обсуди с пользователем.
- **Контент = статика.** Markdown в `public/content/`, метаданные в `index.json`. Бэкенда нет.
- **Генеративные фоны** — визитная карточка проекта. Синергия минималистичного UI и p5.js анимаций. Сохраняй этот баланс.

### CSS-подход

- **CSS Modules** — один `.module.css` файл рядом с компонентом.
- Глобальные стили — только для reset/body/typography в `src/styles/global.css`.
- Дизайн-токены — CSS custom properties в `src/styles/tokens.css`.
- Не используй CSS-in-JS, Tailwind или другие CSS-фреймворки.

### Кастомные компоненты в Markdown

Для интерактивных элементов (квизы, callout, spoiler и т.д.) используй кастомные компоненты через `components` prop react-markdown. Компоненты лежат в `src/components/md/`.

Паттерн активации в markdown — через HTML-совместимые теги или специальные code fence:
```md
<quiz question="Что такое субстрат?" answer="Среда для корней растения" />

:::callout[Важно]
Текст callout-блока
:::
```

При создании нового md-компонента:
1. Создай компонент в `src/components/md/`
2. Зарегистрируй его в маппинге компонентов (единая точка регистрации)
3. Документируй синтаксис в content-guide

## Конвенции кода

### TypeScript

- Strict mode включён. Не используй `any` без веской причины.
- Именование: `PascalCase` для компонентов и типов, `camelCase` для функций и переменных.
- Файлы компонентов: `PascalCase.tsx` + `PascalCase.module.css`.
- Файлы утилит/хуков: `camelCase.ts`.
- Предпочитай именованные экспорты (`export function`) для утилит. Default export — только для страниц и компонентов.

### React

- Функциональные компоненты, без классов.
- Props — через интерфейс, объявленный в том же файле (если не переиспользуется).
- Не оборачивай в `React.memo`/`useMemo`/`useCallback` без измеримой проблемы с производительностью.

### Импорты

Порядок:
1. React и react-* библиотеки
2. Сторонние библиотеки
3. Компоненты проекта
4. Хуки, утилиты, типы
5. Стили (.module.css)

## Тесты

### Когда писать тесты

- **Обязательно:** утилиты и хуки с нетривиальной логикой, кастомные md-компоненты.
- **По запросу:** страницы и UI-компоненты (спроси пользователя, нужен ли тест).
- **Не нужно:** чисто визуальные компоненты без логики, p5.js скетчи.

### Как писать тесты

- Vitest + @testing-library/react.
- Файл теста рядом с модулем: `Component.test.tsx` или `util.test.ts`.
- Тестируй поведение, не реализацию.

## Процесс работы

### Коммиты

- Не коммить автоматически — только по запросу пользователя.
- Сообщения на русском, короткие и по делу.

### Перед любым изменением UI

1. Прочитай текущий код компонента.
2. Сверься с дизайн-системой (.claude/design-system.md).
3. Убедись, что не ломаешь существующую доступность.

### Перед созданием/редактированием контента

1. Сверься с content-guide (.claude/content-guide.md).
2. Подумай о педагогической ценности.
3. Если сомневаешься в подаче — предложи варианты пользователю.

### При неуверенности

Спроси. Лучше уточнить, чем переделывать.
